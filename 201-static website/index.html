Object Storage 정적 웹사이트는 서버에서 코드를 실행하지 않습니다. 브라우저가 필요한 HTML, CSS, JavaScript, 이미지를 객체로 저장하고, 웹사이트 엔드포인트가 요청 경로를 객체 key로 바꿔 응답합니다. 이 예제는 하나의 인터랙션 페이지와 여러 개의 단순 HTML 페이지로 구성되어 있습니다. 버킷 루트에 그대로 동기화하면 `index.html`이 시작 문서가 되고, `css/style.css`, `js/main.js`, `video/001/...` 같은 상대 경로 리소스가 같은 버킷에서 로드됩니다. 강의에서는 업로드, 공개 권한, 기본 문서, 에러 문서, 객체 경로 대소문자 문제를 한 번에 확인할 수 있습니다.

`rooms.html`처럼 개별 파일을 만들면 서버 라우터 없이도 페이지 이동이 가능합니다. 정적 호스팅은 URL path를 객체 key로 해석하고 해당 객체를 그대로 브라우저에 전달합니다.

정적 웹사이트 호스팅을 켜면 `/` 요청은 `index.html`로 연결되고, `/overview.html` 요청은 같은 이름의 객체를 찾습니다. 없는 경로는 지정한 에러 문서나 기본 오류 응답으로 처리됩니다. 이 동작을 이해하면 웹 서버 없이도 공개 웹페이지를 배포할 수 있는 이유가 명확해집니다.

실습 순서는 간단합니다. 파일을 버킷 루트에 올리고, 시작 문서를 `index.html`로 지정한 뒤, 공개 읽기 권한을 설정합니다. 그 다음 웹사이트 엔드포인트로 접속해 CSS, JavaScript, 이미지가 모두 같은 기준 경로에서 로드되는지 확인합니다.

이 예제는 서버 사이드 코드가 없습니다. 그래서 인스턴스, 런타임, 프로세스 관리 없이도 서비스할 수 있지만, 업로드된 객체의 경로와 권한 설정이 틀리면 브라우저에서 바로 403 또는 404로 드러납니다. 그 차이를 보여주는 데 초점을 둔 인터랙션 자료입니다.
